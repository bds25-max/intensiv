# Контур КЦР — Задача 1, v8

Поставка пересобрана из всех четырёх исходных Excel, приложенных вместе с ТЗ. Работа ограничена задачей 1: разбор, нормализация, история и качество данных. Исходные таблицы и документы сохранены без изменения в `sources/`.

Повторный полный запуск даёт побайтно одинаковые шесть выходных файлов.

## Запуск

Требуется Python 3.9 или новее. Распакуйте архив целиком. Откройте терминал в распакованной папке:

```bash
python -m pip install -r requirements.txt
python parser_core.py
python -m unittest test_parser.py -v
python verify_delivery.py
```

Парсер автоматически находит таблицы в `sources/` и записывает шесть основных выходных файлов рядом со скриптом. Тесты проверяют 19 сценариев; при наличии исходников проверка статусов использует и реальные таблицы. `verify_delivery.py` сверяет все листы и заголовки карты, поля истории, координаты объектов, реквизиты с происхождением и количества срезов; затем выполняет дополнительный полный прогон во временную папку и побайтную сверку. Эта проверка занимает больше времени, чем обычные тесты.

## Состав поставки

- `parser_core.py`, `test_parser.py`, `requirements.txt` — код и 19 тестов.
- `normalized_clients.json` — карточки клиентов с реквизитами, отдельными ролями менеджера и администратора и происхождением атрибутов.
- `normalized_slices.jsonl`, `rejected_slices.jsonl` — принятые и отклонённые наблюдения; причины отклонения сохранены.
- `normalized_history.jsonl` — статусы, комментарии, сроки и материалы коммуникаций.
- `quality_report.json`, `quality_report.csv` — проблемы с координатами, исходными значениями и действиями.
- `column_mapping.md` — карта всех 188 колонок с фактическими заголовками и заполненностью.
- `column_coverage.json` — машиночитаемая карта и результат сверки с таблицами.
- `source_preserved_values.jsonl` — 11 694 исходные ячейки истории и колонок, исключённых из основных схем. Содержит координаты, исходное значение, тип Excel и доступное кешированное значение формулы. Среди них 4 543 непустые ячейки исключённых колонок; они сохранены без назначения им новой бизнес-семантики. В отличие от основных текстовых полей, исходные строки в этом файле сохраняют внешние пробелы.
- `verification_result.json`, `VALIDATION.md` — результаты проверки.
- `TZ1_CHECK.md`, `OPEN_QUESTIONS.md` — сверка с ТЗ 1 и нерешённые вопросы.
- `contract.md`, `examples.json`, `context.md` — описание формата и небольшие примеры, выбранные из фактического результата.
- `sources/` — четыре исходных Excel и шесть документов из TZ.zip.
- `SHA256SUMS.json` — контрольные суммы файлов поставки, кроме самого списка сумм.

Основные текстовые поля используют прежнее удаление пробелов по краям. Маскирование имён, телефонов, email и комментариев не выполняется. Для точного восстановления исходных строк и отдельных полей инцидента используйте дополнительный исходный набор и неизменённые Excel.

## Ограничения

2 202 среза без total остаются отклонёнными по текущему правилу; их количества не выдумывались и не подставлялись. 243 неизвестных клиента не превращены в новые карточки. 295 январских наблюдений с противоречием годов в заголовках изолированы. Эти данные требуют рассмотрения; код не подтверждает бизнес-трактовку спорных полей. Подробности — в OPEN_QUESTIONS.md.

Настоящая поставка не выполняет задачи 2–4, не создаёт БД, не рассчитывает категории динамики и не отправляет сообщения клиентам.
