# Изменения v9

## Три исправления

1. Неверная дата создания больше не попадает в поле календарной даты: исходное значение хранится в raw_creation_date, а отчёт содержит INVALID_CREATION_DATE с координатами D. Проверены свободный текст, несуществующая дата, корректная дата и пустая ячейка.
2. Код и название СЦ сохраняются раздельно: service_center_code и service_center. Проверены оба заполненных поля и случаи заполнения только одного из них. Контракт обновлён без удаления прежних полей.
3. Процент повтора без total проверяется по окончательно принятому опорному количеству. При total=10, unsent=2 и raw_percentage=0.9 формируется PERCENTAGE_MISMATCH с расчётной долей 0.2. Повтор остаётся принятым, исходные поля не подменяются. Конфликтующие/отклонённые опоры для проверки не используются.

## Рефакторинг после исправлений

Карта 188 колонок перенесена в column_mapping.json с сохранением экспорта COLUMN_MAPPING из parser_core. Обработка клиентских атрибутов объединена в enrich_client_from_columns по трём явным картам и карте квартального листа. Сохранены порядок источников, приоритет заполненных значений и происхождение каждого атрибута. Проверки опор, отсутствующего total и процентов разделены на методы QualityAuditor. Две реализации сверки процента заменены одной.

Точка входа python parser_core.py, parse_all_kcr и его пять коллекций сохранены. Основные классы и импортируемые функции не переименованы. Для запуска нужен файл column_mapping.json рядом со скриптом.

После исправлений, до рефакторинга, выполнены 25 тестов и сохранён контрольный экспорт. После рефакторинга те же 25 тестов проходят. На реальных таблицах все шесть выходных файлов совпали с контрольным экспортом побайтно. Результат сравнения и хеши — в refactor_comparison.json.

## Что не менялось по смыслу

Вопросы 2 202 наблюдений без надёжного total, 295 январских наблюдений с неоднозначным годом и 243 неизвестных клиентов остались открытыми. Исходные Excel и документы не исправлялись. Отдельные данные не заполнялись вымышленными значениями.
