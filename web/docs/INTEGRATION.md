## Предложение API 0.1

`contracts/openapi.json` фиксирует минимальные формы обмена текущего демо. Это не согласованная схема сервера.

- GET `/state`: состояние рабочего места; для оператора только доступные клиенты.
- POST `/actions`: демонстрационные команды (назначение, звонок, претензия и др.). Реальный сервер может разделить их на ресурсы. После согласования изменить адаптер, не формы.
- `source_client_id` из контракта v9 должен быть отображён в строковый `Client.id`; leading zeros не удалять.
- Даты API: ISO, пустые значения null, время события и внесения отдельно. Модель демо использует даты без часового пояса; согласовать реальные datetime с №5.
- 401: сессия; 403: права; 404: недоступный клиент; 409: конфликт назначения и обновление карточки; 422: поля формы.
- Автор и права только из серверной сессии. Браузер не является источником истины.

## Обязательные изменения перед приёмкой с API

1. Обновить OpenAPI и перегенерировать типы; убрать предположения демонстрационных DTO.
2. Реализовать загрузку multipart, получение статуса фоновой задачи и подтверждение preview token. Не использовать фиксированные демо-счётчики.
3. Получать динамику и объяснения из расчётов №3; в текущем демо сравнения рассчитаны для макета.
4. Передавать все условия фильтра серверу и показывать независимую проверку каждого условия, а не считать допуск публикации на клиенте.
5. Связать события с действительными разрешёнными переходами №4, required-полями и idempotency key.
6. Реализовать восстановление сессии через `/me`, серверный logout, CSRF-механизм, ошибки блокировки пользователя и безопасный сброс пароля.
7. Подключить маршруты №7. Сводка только по данным сервера, все даты/числа со ссылками; unsupported text не терять. Фронтенд не делает самостоятельных запросов к модели.
8. Провести реальные браузерные тесты прав, параллельного назначения и обоих циклов брифа. После замены моков требуются интеграционные проверки с коллегами.

## Среда

Vite статически собирает SPA в dist. Веб-приложение можно обслуживать обычным HTTP-сервером. Адрес API задаётся при сборке, это не секрет. Ключи моделей никогда не добавлять в переменные VITE_ или фронтенд. Рекомендуется один origin с reverse proxy на сервер №5; если origin разный, согласовать credentialed CORS и cookie policy.
