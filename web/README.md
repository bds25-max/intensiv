# Контур КЦР — веб-интерфейс, ТЗ №6

Рабочая первая версия на React + TypeScript. **Это демо интерфейса, не готовый сервер КЦР.** До появления ТЗ №5 и №7 запросы обрабатывает отдельный демонстрационный транспорт, данные сохраняются локально в браузере. Исходные Excel и клиентские JSON заказчика в проект не включены.

## Быстрый запуск

Нужен Node.js 22+.

```bash
npm ci
npm run generate
npm run dev
```

Открыть адрес, который напечатает Vite. Демо-логины: `admin`, `anna`, `ivan`. Пароль всех вымышленных пользователей: `demo`. Выбор роли на экране входа заполняет форму. Новый демо-пользователь тоже получает пароль `demo`.

```bash
npm test
npm run build
```

Для браузерных тестов на своей машине:

```bash
npx playwright install chromium
npm run test:e2e
```

Проверка через уже запущенный стенд: `KCR_TEST_URL=http://localhost:5173 npm run test:e2e`.

## Что работает

- Вход в демо под администратором и двумя операторами; разные пункты навигации.
- Поиск по коду, ИНН и названию; период, фильтры, сохранение фильтра, сортировка, пагинация.
- Выбор клиентов вручную, проверка основных условий и блокирование публикации списка с открытыми циклами.
- Опубликованный пул, назначение с ожидаемой версией, освобождение и передача администратором.
- Карточка: периоды отдельно, история всех срезов, динамика, ответственный, события и прошлые претензии.
- Форма звонка, договорённость, срок клиента, следующее действие, письмо, завершение цикла.
- «На сегодня», просроченные действия, изменение остатка.
- Демо-предпросмотр импорта, проблема неизвестного клиента, фильтр проблем, CSV, подтверждение, журнал.
- Претензии и санкции; создание и смена статусов сохраняют события.
- Демо-пользователи: создание, блокировка, сброс демонстрационного пароля.
- Предпросмотр сводки с источниками и состояние недоступного помощника.

## Границы этой версии

1. **Реальный Excel не разбирается.** Файловое поле показывает выбранное имя. «Открыть демо-предпросмотр» использует встроенный сценарий; файл не отправляется. Типы справочника/истории показаны как будущие варианты API, но текущий демо-импорт демонстрирует только срез.
2. **Модель ИИ не вызывается.** Сводка — детерминированный предпросмотр; естественный язык не переводится в условия. Неразобранный запрос показывается полностью и предлагается ручной фильтр.
3. **Демо-вход не является защитой данных.** В браузере нет серверных HttpOnly-сессий, хеширования паролей, транзакций или настоящей проверки прав. `mock.ts` имитирует ответы для проверки UI; использовать его с данными заказчика нельзя.
4. Выборка проверяет демонстрационные условия. Независимая проверка всех условий и окончательное разрешение публикации — обязанность API №5.
5. Не подключены готовые реализации ТЗ №2–4: в переданном архиве есть их задания, но не результаты коллег. Предварительные этапы и статусы из архитектуры требуют сверки с переданным коллегами каталогом.
6. Полный сквозной сценарий с реальными Excel, настоящими API и ИИ не принят. Производительность на 5 874 клиентах не измерена.

## Структура

- `src/main.tsx`, `src/style.css`: интерфейс и компоненты.
- `src/api.ts`: единая точка транспорта; `openapi-fetch`, cookies включены.
- `contracts/openapi.json`: **предложение** контракта 0.1, не контракт готового API №5.
- `src/schema.d.ts`: сгенерированные типы, не редактировать вручную.
- `src/mock.ts`: демонстрационный обработчик; не переносить его правила в реальный фронтенд.
- `src/fixtures.ts`: вымышленные клиенты, фиксированная дата демо 02.11.2026.
- `tests/workflow.test.ts`: автоматические проверки демо-обработчика.
- `tests/e2e/scenario.spec.ts`: Playwright-сценарии UI.
- `docs/INTEGRATION.md`: передача исполнителям №5 и №7.
- `docs/ACCEPTANCE.md`: готовность и подтверждения.

## Подключение сервера

Сначала согласовать OpenAPI с исполнителем №5. В текущем проекте два предварительных маршрута `/state` и `/actions`; они не выдаются за фактические маршруты будущего FastAPI. После согласования заменить схему, выполнить `npm run generate`, привести `src/api.ts` к маршрутам сервера и подключить импорт файлов и AI по их согласованным контрактам. Только после этого указать `VITE_API_BASE_URL`, пересобрать и провести интеграционные тесты.

Если сервер реализует именно предложенную схему, обычные действия подключатся сменой адреса; импорт файлов и помощник всё равно требуют отдельных согласованных маршрутов. Проверка данных, динамики и процесса — на сервере через библиотеки №1–4.

## Как показать демо

1. Войти как admin. В «Формировании пула» выбрать клиента DEMO-004; опубликовать.
2. Выйти, войти как anna. В пуле открыть DEMO-004, взять в работу и сохранить звонок со следующим действием.
3. Выйти, войти как admin. В «Загрузке данных» открыть демо-предпросмотр и подтвердить.
4. В «Разборе среза» открыть группу «В работе». Ответственный и цикл сохранены; новый срез записан в историю.
5. Создать претензию в открытой карточке, изменить статус. Оба действия видны в истории.
6. Для повторного цикла закрыть цикл через форму звонка, затем посмотреть историю и претензию; сбросить демо для нового прогона.

«Сбросить демо» восстанавливает только вымышленный набор этого браузера. Состояние разных устройств не синхронизируется. Две вкладки одного браузера обновляются через storage-события, но это не замена конкурентных транзакций сервера.
