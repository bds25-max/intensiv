# Контекст проекта: Контур КЦР (Задача 1)

## Описание предметной области
Проект «Контур КЦР» направлен на оптимизацию процесса сбора оригиналов документов с Центров Регистрации (КЦР). В настоящее время исторические данные и оперативные срезы хранятся в разнородных Excel-файлах с отличающейся структурой.

## Цель Задачи 1 (Разбор Excel и единый формат)
Разработать автономный модуль для парсинга четырёх исходных Excel-таблиц, приведения данных к единому нормализованному JSON-контракту и формирования отчёта о качестве данных без необходимости подключения к базе данных (PostgreSQL).

## Исходные файлы
1. **КЦР_последняя выгрузка_Дубна.xlsx**
   - Основная база клиентов (5 874 записи) и ретроспективные срезы сдачи документов.
   - Особенности: строка заголовка находится на строке 2; ячейка A2 пуста (заголовок пропущен); строка 5877 содержит служебные суммы.
2. **Срез 20.10.26_Дубна.xlsx**
   - Оперативные срезы по 4 периодам: «весь 2025 год», «1 кв 2026», «2 кв 2026», «3 кв 2026».
   - Особенности: заголовок на строке 2 («Уникальны обезличинный идентификатор»); на листе «3 кв 2026» присутствуют 243 клиента, отсутствующие в основной базе; на листах «весь 2025 год» и «1 кв 2026» есть дубликат клиента `ISE83063`.
3. **База должники III кв 2025 Дубна.xlsx**
   - История работы операторов ООВС, комментарии к звонкам, статусы и сроки.
   - Особенности: строка заголовка на строке 1; строка 297 содержит итоги суммирования.
4. **База I кв 2026 Дубна.xlsx**
   - Данные по второму касанию операторов, даты перезвона и обязательства клиентов.
   - Особенности: строка заголовков на строке 2.

## Межмодульное взаимодействие
- **Входы**: Исходные файлы Excel в рабочей директории.
- **Выходы**:
  - `normalized_clients.json`: реестр клиентов (`source_client_id`, `is_active`, `is_blocked`, `provenance`). Передаётся Задаче 2.
  - `normalized_slices.jsonl`: плоские наблюдения срезов (`source_client_id`, `period_start`, `period_end`, `as_of_date`, `total`, `unsent`, `raw_percentage`, `provenance`). Передаётся Задаче 2 и Задаче 3.
  - `normalized_history.jsonl`: хроника коммуникаций операторов с клиентами (`source_client_id`, `event_type`, `occurred_at`, `text`, `raw_status`, `raw_deadline`, `provenance`). Передаётся Задаче 4.
  - `quality_report.csv` / `quality_report.json`: аудит расхождений и аномалий в данных.
